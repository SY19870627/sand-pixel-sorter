# Sand Pixel Sorter Web Prototype

這是一個可在瀏覽器執行的 `Sand Pixel Sorter` 原型。

## 執行方式

直接用瀏覽器開啟：

```text
D:\Git\Idle Sand Sorting\index.html
```

目前 Web 版使用 `Phaser 3 + Matter Physics` 負責 Canvas 場景、圓球沙粒、剛體碰撞、重力、滾動、吸入粒子與輸送帶顯示。核心規則仍保留在純 JavaScript 狀態模型中，方便之後接 AI 求解或關卡驗證。

目前沙子採用「Particle Object + Matter Body」：

- 每顆沙都是 `SandParticle` 物件，保存 `id`、`color`、`gridX`、`gridY`、`x`、`y`、`state`。
- 每顆沙在 Phaser 場景中都有一個 Matter 圓形剛體。
- 水桶只吸「該桶目前 X 軸正上方」且位於畫框底部範圍內的同色沙。
- 沙粒材質使用低彈性、高摩擦、高阻尼設定，避免像橡膠球一樣回彈。
- 吸走一顆沙後，周圍沙球會受重力、碰撞、摩擦與微弱側向擾動自然下落或滾動。

## 原型規則

- 每個像素格是一個垂直堆疊。
- 上方顯示的是完整像素沙畫；目前沙畫解析度為 `48x48`。
- 每格目前只有一層沙畫顏色；吸完後該格會直接變空，不會露出隨機填充色。
- 吸走一格後，同一欄上方的沙會往下掉補位。
- 水桶放入 5 格輸送帶後會自動吸同色底層。
- 玩家可以連續放桶；吸收迴圈會在背景持續處理所有啟動中的水桶。
- 多個水桶同時啟動時採用輪流吸收，每一輪每個桶最多吸 `1` 顆沙球。
- 吸收動畫已加速：每輪多桶可並行吸收，單顆吸入 Tween 約 `68ms`。
- 吸收採用串流判定：第一顆吸入動畫尚未結束時，約每 `12ms` 會重新判斷是否能接著吸下一顆。
- 輸送帶槽位會持續往右移動，超過最右側後循環回到最左側。
- 輸送帶左右兩側有最上層遮罩，隱藏桶子循環回到左側的瞬間位移。
- 放桶時會選擇畫面上 X 座標最左邊的空槽，而不是槽位編號最小的空槽。
- 右側介面已極簡化，只保留水桶按鈕。
- 本原型每吸一層算 `10` 單位，水桶容量是 `100`。
- 水桶滿 `100/100` 後會消失並釋放槽位。
- 若 5 個槽位全滿，且沒有任何水桶顏色符合目前底層可吸顏色，判定死鎖。

## 下一階段效能計畫

目前版本讓每顆細沙都建立 Matter 圓形剛體。這能快速做出重力、碰撞與滾動感，但當沙粒數量增加時，效能會明顯下降。後續優化請依序執行，不建議直接跳到大型重構。

### 階段 1：Matter 局部休眠 / 局部喚醒

- [ ] 建議分支：`perf/local-wakeup`
- [ ] 重新開啟 Matter sleeping，避免全場靜止沙球每幀都跑物理。
- [ ] 每次吸走沙子後，只喚醒吸收點上方與附近幾列沙球。
- [ ] 使用 `Matter.Sleeping.set(body, false)` 喚醒局部 body。
- [ ] 驗證沙子仍會往下掉。
- [ ] 驗證玩家能連續放桶。
- [ ] 驗證效能不能比全場不休眠更差。
- [ ] 完成後提交 commit。

下次執行提示詞：

```text
請建立 Git 分支 perf/local-wakeup，實作 Sand Pixel Sorter 的 Matter 局部休眠與局部喚醒。保留目前球體沙子玩法，重新開啟 enableSleeping，但在每次吸走沙子後，用 Matter.Sleeping.set(body, false) 只喚醒吸收點上方與附近幾列沙球。完成後請測試沙子會往下掉、連續放桶正常、效能不能比全場不休眠更差，最後做一個 commit。
```

### 階段 2：混合架構，只讓可動沙子進 Matter

- [ ] 建議分支：`perf/hybrid-sand-bodies`
- [ ] 靜止沙畫不要全部建立 Matter body，改用輕量方式渲染。
- [ ] 桶子吸走底層沙子後，只把該欄位與附近會鬆動的沙子轉成 Matter 球體。
- [ ] 沙子落定後，再寫回靜態沙畫資料。
- [ ] 保留目前輸送帶、水桶吸收、連續吸沙邏輯。
- [ ] 驗證畫面仍像沙子流動。
- [ ] 驗證場上的 Matter 物件數大幅下降。
- [ ] 完成後提交 commit。

下次執行提示詞：

```text
請建立 Git 分支 perf/hybrid-sand-bodies，將 Sand Pixel Sorter 改成混合架構：靜止沙畫不要全部建立 Matter body，只用輕量方式渲染；當桶子吸走底層沙子後，才把該欄位與附近會鬆動的沙子轉成 Matter 球體。沙子落定後再寫回靜態沙畫資料。請保留目前輸送帶、水桶吸收、連續吸沙邏輯，完成後測試並 commit。
```

### 階段 3：Active-Set Cellular Automata 正式沙流核心

- [ ] 建議分支：`engine/active-set-ca`
- [ ] 將沙畫本體改成 `grid` 儲存。
- [ ] 每次吸沙只把受影響欄位與鄰近欄位加入 `active queue`。
- [ ] 每幀只更新 active cells。
- [ ] 沙流規則優先順序為：下、左下、右下。
- [ ] 視覺上仍要像細小圓形沙粒，不要回到大格子感。
- [ ] 保留輸送帶與水桶 X 軸吸收邏輯。
- [ ] 驗證支援更細沙粒且效能穩定。
- [ ] 完成後提交 commit。
